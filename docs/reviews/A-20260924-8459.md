## Findings reported to claude-ab

claude-ab filed the substance as CFG-0582 to CFG-0588 in `~/.claude`. The
detail and the reproductions are here.

1. **v2 skills cannot be loaded for one project.** The adoption skill's
   first step is `Skill: orient`, which is not installed. The session saw
   only the live v1 skills, including v1 `adopt-project`, which is
   read-only. `orient` was executed by hand from `draft/v2`.
2. **The copied hooks would have checked nothing.** The skeleton's
   delegators run `${CLAUDE_HOME:-$HOME/.claude}/hooks/...`. `CLAUDE_HOME`
   was unset, and neither `~/.claude/hooks/pre-commit` nor `~/.claude/tools`
   existed. Each commit would print "NOTHING WAS CHECKED" and exit 0.
   The skeleton's `settings.json` points at a missing
   `$HOME/.claude/hooks/no-hand-edit` the same way. claude-ab reports this
   fixed in `~/.claude` commit `ce25937`: a project that declares
   `.claude/workflow.json` now has a missing hook refuse, naming
   `HOOK_SKIP=missing`. This session verified that fix in a throwaway clone
with the owner's approval. The clone had the two skeleton delegators in its
`.githooks/`, and `CLAUDE_HOME` was unset:
   - With `workflow.json` present, the commit was refused with exit 1,
     naming the missing hook and `HOOK_SKIP=missing`.
   - With `workflow.json` removed, the commit passed with a "NOTHING WAS
     CHECKED" warning.
   - With `HOOK_SKIP=missing` set, the commit passed. `commit-msg`
     recognised the adopted case in its message.

   `commit-msg` refusing on its own was not observed, because `pre-commit`
   refused first in the refusal test.
3. **The workflow's own retirements have nowhere to live.** `deadnames`
   reads only the project's `dead_names` map. Declaring review-contract,
   write-spec, check-doc-facts, verify-delivery and review-ledger there
   produced 34 report lines. Almost all of them fell on records that must
   not be edited, or on the store-rendered `ROADMAP.md`. The map was
   reverted. Each hit was also reported twice: once by the hook's own
   check, and once by `check-doc`'s.
4. **v1 names are still routed to from instruction files:**
   - `CLAUDE.md` release step 1 → `versioning.md` § 2.
   - `docs/standards/versioning-overrides.md` → all of `versioning.md`.
   - The GHUB-0161 spec → `languages/qt.md`.
   - `docs/design.md` → `workflow.md` § 2 and `documentation.md` § 9.1.
   - `CLAUDE.md` and `docs/design.md` → `review-contract`.

   v2 has no versioning standard, so the overrides file cannot become a
   `deviations` entry.
5. **`boundaries` has no reader** in any v2 skill, tool or hook, and the
   shape of its list entries is unspecified. `security.md` claimed that
   `declaration.md` had no key for a pin's reason, but `holds` is that key.
   claude-ab reports the `security.md` line fixed.
6. **Reconciling a status line trips another check.** The specs'
   `**Status:** accepted (date) — ...` lines became `Status: active`. That
   moved their history into body prose, which the `history` check flags.
7. **The `docs/design.md:416` path finding** is reported fixed in
   `ce25937`: a bare word after a slash is now treated as vocabulary, not a
   file.
8. **No conflict with the machine-wide push gate.** Games_Hub sets its own
   `core.hooksPath=.githooks`, and its `pre-push` runs
   `scripts/local-ci.sh`, not `~/.claude/githooks/pre-push`.
